С 2026-09-16 данные находятся в `../setos-backend/local-data/SETOS/` относительно
корня репозитория. Не создавайте данные в Library/Application Support.

## Основной режим: фото и видео в браузере

Дважды открой **Camera Coach — Разметка.command** на рабочем столе.
Откроется локальная страница; повторный запуск открывает уже работающий
разметчик, не создавая второй процесс оплаты. Окно Terminal оставляй открытым.

1. Разметчик сам ставит текущий и следующие пять материалов в фоновую очередь.
   Платный запрос выполняется только один за раз; готовый результат кэшируется
   по SHA медиа, модели, промпта, схемы и рецепта уменьшения.
2. Посмотри фото или воспроизведи видео и проверь написанные моделью проблемы,
   действия и пространственные цели.
3. Если согласен, нажми `Enter`: предложение сохранится как подтверждённая
   человеком assisted-разметка и откроется следующий материал.
4. Если не согласен, нажми `E`, напиши своё мнение и нажми `⌘Enter`.
   Модель переведёт его с учётом видимого кадра. Проверь перевод и подтверди
   `⌘⇧Enter`. Каждый новый перевод правки — отдельный платный запрос.
5. Без ключа или при ошибке можно **Сохранить только текст**, чтобы не потерять
   мнение. Оно останется неструктурированным до последующей обработки.

Горячие клавиши вне полей: `Enter` — принять готовый авторазбор, `E` — перейти
к правке, `S` — пропустить, `B` — назад, `Space` — пауза/воспроизведение видео.
В поле текста: `⌘Enter` — разобрать, `⌘⇧Enter` — подтвердить, `Esc` — выйти.

Ключ вводится в «Настройки Command Code» и хранится только в памяти процесса.
После остановки сервера его потребуется подключить снова. Автоматических
платных повторов нет. Command Code не даёт этому инструменту баланс или
стоимость в деньгах, поэтому вместо ложного RUB-бюджета действует жёсткий
лимит в 100 запросов на журнал. Он общий для фонового анализа и ручных правок.
Неизвестная стоимость оборванного запроса блокирует новые разборы до сверки;
сохранение текста остаётся доступным.

Выбрана `meta/muse-spark-1.3-contributor`. Её проверка через Command Code
вернула `cmd_zdr_no_providers`, поэтому заголовок ZDR намеренно не посылается:
мы не подменяем выбранную модель. В API уходит JPEG с длинной стороной до
1024 px; для видео — только три существующих кадра (начало, середина, конец),
не сам видеофайл. Не используй этот режим для приватных медиа без согласия.

Очередь содержит 300 фото предыдущего пилота и 84 существующих клипа,
без копирования медиа. Журнал и очередь находятся вне Git:

```text
/Users/unterlantas/Documents/XCode/setos-backend/local-data/SETOS/annotation/language-review-20260915/
  queue.jsonl
  opinions.jsonl
  server.lock
```

`visual_dispatch` записывается до фонового API-вызова, `visual_proposal` —
неподтверждённая подсказка, `visual_confirmed` — явное согласие человека.
Для правки исходные слова сохраняются до API-вызова: `proposal` — перевод,
`confirmed` — его подтверждение, `raw` — только текст.
Исправления дописываются, история не удаляется. Сервер связывает отзыв с
SHA-256 медиа, а для отправленных JPEG пишет только SHA/размер/рецепт, не
base64-пиксели или ключ. Цитаты из ручной правки проверяются дословно.
Черновик в браузере не заменяет
запись в журнале: нажимай одну из кнопок сохранения/разбора перед закрытием.

### Что это даёт обучению, а чего пока не даёт

Это assisted research-разметка, а не автоматическая истина или новый
production-контракт сети. Неназванные в ручной правке проблемы и действия
остаются неизвестными.
«Всё нормально» не исключает автоматически все восемь проблем; «темно»
не доказывает контровой свет. Отрицания переводятся в явные запреты.
Замечания вне словаря сохраняются дословно, не теряются.

`contract_projection` сохраняет `training_ready=false`. Отдельный явный
`export-language` теперь создаёт typed intake **v2.1.0** с частичными масками
проблем: `1` — названа проблема, `0` — явно отмечено её отсутствие, `null` —
неизвестно и не участвует в loss. Старый формат v2.0.0 остаётся прежним.
Нельзя отправлять саму projection напрямую в `parse_record` или подменять
неизвестные значения отрицательными. Для остальных heads нужны новые
grounding/intent/action данные и отдельный допуск.
Запросы вроде «стол ближе к центру» сохраняются как `spatial_requests`, но не
превращаются в обучаемые v2-deltas до отдельного допуска пространственного
контракта. ROI, точные сдвиги/зум, risk и abstention не выдумываются.
«Стало лучше» в видео — оценка человека, не доказательство выполнения совета;
`viewed_at_s` — позиция плеера при отправке, не размеченный интервал события.

Все записи, включая принятые человеком авторазборы, сохраняют
`research_only=true`, `human_gold=false`,
`release_admissible=false`. Языковая помощь явно обозначена; эти записи
нельзя незаметно смешивать с прежними blind gold-контролями.

Экспорт создаёт новую папку с `records.jsonl`, полным происхождением в
`lineage.jsonl`, проверкой существующих source-group splits и receipt с SHA.
Исходные очередь, журналы и медиа не изменяются. Более новая ручная правка
снимает прежнее подтверждение с обучения; неподтверждённые предложения и
locked test в intake не попадают. Поисковая категория используется только
для sampling; она не становится scene-class target. Accepted visual proposals
и переведённые человеческие мнения имеют разные `label_origin`.

Из корня репозитория, указав новое имя выходной папки:

```bash
python3 -B tools/camera_annotation/review_pipeline.py export-language \
  --folder ../setos-backend/local-data/SETOS/annotation/language-review-20260915 \
  --out ../setos-backend/local-data/SETOS/annotation/partial-intake-new
python3 -B -m ml.camera_coach.data.check_partial_labels \
  --intake ../setos-backend/local-data/SETOS/annotation/partial-intake-new \
  --out ../setos-backend/local-data/SETOS/annotation/partial-intake-new/gradient-check
```

Вторая команда проверяет реальные train-пиксели, preprocessing, loss и
градиенты; optimizer не запускается, validation не используется для настройки.
Пустые supervision и конфликты сплитов не дают PASS. Assisted validation
остаётся исследовательской; авторская группа и dHash не доказывают независимость
сцен или качество советов. Контракт: `ml/camera_coach/contracts/camera_training_record_v2_1.md`.

Разработчику: `python3 -B tools/camera_annotation/language_labels.py` и
`python3 -B tools/camera_annotation/language_review.py --self-check` проверяют
контракт, пространственные цели, JPEG-дериватив, allowlist и остановку worker.

## Запуск на этом Mac

Запусти команду расширенного режима выше. Это существующее
Python/Tk-приложение, не новая функция iOS.

Рабочая папка:

```text

```

Сначала инструмент открывает 100 кадров без подсказок (`blind`). После их
разметки закрой окно и запусти ярлык снова: откроется очередь из 200 кадров
для проверки предложений модели (`assisted`). Закрывать и продолжать можно
в любой момент; сохранённые кадры текущего разметчика пропускаются.
Кнопка «Назад» позволяет исправить решение в текущей сессии. Для просмотра
ранее завершённой очереди напрямую укажи `annotate_gui.py --redo`.

Начни с **20 кадров**, затем сообщи, что они готовы. Это проверка понятности
инструкции и структуры меток, а не достаточный набор для обучения.
Массовую разметку лучше продолжить после проверки этих первых решений.

## Что делать на каждом кадре

1. Выбери тип сцены по изображению. Поисковый запрос источника не является
   правильной меткой: среди «предметов» могут оказаться здания и памятники.
2. Проверь замысел. В этом пилоте задана задача «естественный кадр»;
   это не утверждение о намерении автора фотографии. Для оценки силуэта,
   симметрии и других стилей явно выбери соответствующий замысел.
3. Отметь «красиво / пограничное / некрасиво». Красивый кадр может допускать
   улучшение, поэтому галка «Нужно улучшать» — отдельное решение.
4. Выдели мышью главного субъекта и задай роль `subject`. Для группы людей
   используй одну общую область, если группа — единый субъект.
   Если выделить главного субъекта обоснованно нельзя, явно отметь
   неопределённость ROI; не рисуй случайный прямоугольник.
5. Если улучшение нужно, выбери видимую проблему и полезное действие.
   Для «переставить лампу» выдели отдельную область `target` или `distractor`
   и подпиши, какую именно лампу имеешь в виду. В заметке объясни причину.
   Направления «влево/вправо» указывай относительно показанного кадра.
6. Если совет не нужен, сними «Нужно улучшать» — сохранится KEEP.
   В списке запрещённых действий отмечай только явно оценённые вредные
   действия. Невыбранные действия остаются неизвестными, не отрицательными.
7. **Не угадывай** сантиметры, точный зум, наклон, физическую безопасность
   и возможность двигать чужие предметы по одной фотографии.
   Численные delta-поля оставляй выключенными без измеримого основания.
8. Если решение сомнительно, отметь «Не уверен». Запись сохранится для
   разбора, но её оценка, проблемы и действия не станут обучающими целями.
9. Подтверди, что это твоё решение, затем «Сохранить и далее».

Панель справа прокручивается. Горячие клавиши работают вне текстовых полей:
`1/2/3` — оценка, `K` — KEEP, `U` — не уверен, `Enter` — сохранить,
`S` — пропустить без сохранения, `B` — назад, `F` — вписать изображение.
Пропущенный без сохранения кадр появится при следующем запуске.

## Предложения модели и человеческие решения

В assisted-режиме предложение можно применить в редактируемую форму,
исправить или полностью отвергнуть. Оно никогда не сохраняется само.
Проверь области, замысел, проблему и целесообразность совета, а не только
грамматику объяснения. Если предложение не прошло проверку структуры,
кадр остаётся доступен для ручной разметки без него.

Просмотр подсказки сохраняет признак `assisted`, даже если решение затем
переписано. Первые 100 кадров не отправляются модели и не показывают
эвристики/оценки корпуса: это отдельная контрольная часть.

Сырые ответы модели находятся в `teacher-batch-*/results.jsonl`.
Ручные решения — **только** в `labels-blind.jsonl` и `labels-assisted.jsonl`.
Они дописываются с flush/fsync, исправление не удаляет предыдущую запись.
SHA-256 и читаемость исходного изображения проверяются перед сохранением.
Переставлять/заменять файлы изображений во время разметки нельзя.

Историческое название схемы `camera-human-gold-label-v1` не означает
автоматическое получение gold-статуса. Этот пилот остаётся research-only;
нет независимого согласования, допуска к релизу и измеренной точности модели.

## Проверка и экспорт для разработчика

Команды выполнять из корня репозитория; `PILOT` — отдельная переменная задачи:

```bash
PILOT='/Users/unterlantas/Documents/XCode/setos-backend/local-data/SETOS/annotation/pilot-20260914-v4'
python3 -B tools/camera_annotation/review_pipeline.py report \
  --pilot "$PILOT/pilot.jsonl" --labels "$PILOT/labels-blind.jsonl"

# После получения ручных решений. Добавлять только реально существующие stores.
# out должен быть новым, существующий экспорт не перезаписывается.
python3 -B tools/camera_annotation/review_pipeline.py export \
  --pilot "$PILOT/pilot.jsonl" --labels "$PILOT/labels-blind.jsonl" \
  --out "$PILOT/export-reviewed-01"

python3 -B tools/camera_annotation/review_pipeline.py self-check
python3 -m pytest -q tools/tests/test_annotation_labels.py tools/tests/test_annotation_roundtrip.py
```

Экспорт содержит `records.jsonl`, `review-lineage.jsonl`, `receipt.json`.
Каждая обучающая запись проходит настоящий `parse_record` из
`ml/camera_coach/data/training_records.py`, без создания нового ML-контракта.
Для этого пилота использовать именно `review_pipeline.py export`, а не
исторический `annotation_labels.training_targets` с другими масками.

Маски экспорта:

- Оценённые issues могут обучаться независимо от выбора действия.
- Utility, good-frame и deltas требуют известного замысла и одного субъекта.
- Невыбранные действия неизвестны; отрицательны только явно forbidden.
- `borderline` не превращается в выдуманное бинарное значение good-frame.
- `unsure` не становится положительной меткой abstention.
- Risk, abstention, scene logits и subjectness не размечены этой формой.
  Тип сцены формы — поле стратификации `matrix_class`, не подмена scene logits.

Без человеческих решений экспорт отказывается создавать «обучающий» набор.
При нескольких аннотаторах на один кадр требуется отдельное согласование.
Уверенность учителя не трактуется как калиброванная вероятность.

## Платная подготовка assisted-очереди

Используется уже существующий проверяющий TLS транспорт Polza. Ключ вводится
скрыто или передаётся через `POLZA_API_KEY`, не пишется в конфигурацию/логи.
Передаются только SHA-проверенные публичные Commons-изображения этого пилота,
уменьшенные до 1024 px, а не личная библиотека пользователя.
Конфигурация сохраняет модель, промпт, схему, хеш очереди и хеш программы.

До каждого запроса пишется и синхронизируется `pending`, затем отдельная
строка результата. При продолжении перечисляй ВСЕ прежние журналы через
повторяемый `--exclude-results`: неоднозначно оплаченный запрос не повторяется.
Неизвестная стоимость/ошибка транспорта останавливает партию. Резерв запроса
считается по полным пределам контекста/ответа и RUB-тарифам текущего каталога;
жёсткий финансовый предел остаётся лимитом аккаунта провайдера.
Успешная проверка JSON не является доказательством правильности совета.

## Что ещё нужно до обучения и релиза

Пилот — не полное покрытие сценариев и не готовый production-датасет.
После первых 20 решений проверить полноту/понятность разметки, распределение
KEEP/коррекций, пригодность ROI и покрытие действий. Затем расширять именно
недостающие классы, а не набирать ещё тысячи красивых кадров без разметки.

Разделение 200 train / 100 validation сделано до запросов учителю по
нормализованному имени автора (153 группы), с дедупликацией пикселей.
Это снижает утечки, но разные подписи одного автора и похожие сцены требуют
дополнительной проверки. 100 кадров — пилотная validation, не окончательный
замороженный release-тест. Ассистированная разметка одним человеком также
не заменяет независимое согласование спорных случаев.

Для temporal-проверки нужны отдельные эпизоды «совет → действие → результат»:
выполнен / не выполнен / неверный объект / движение только камеры /
несопоставимые кадры. Последовательность красивых кинокадров этого не даёт.
Пары синтетических искажений дают известные геометрические цели, но не
доказывают полезность перестановки реальной лампы.

После проверки и дополнения разметки — dataset admission, небольшой
Colab-прогон по существующему v2-контракту, сравнение на независимых сценах,
затем калибровка, риск/abstention и проверки на устройстве. В этой задаче
обучение, iOS runtime, production bundle и App Store-допуск не меняются.
