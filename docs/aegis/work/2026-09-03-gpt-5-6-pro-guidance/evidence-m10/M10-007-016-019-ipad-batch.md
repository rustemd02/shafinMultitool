## M10-007 — Camera controls iPad

The control hierarchy is container-driven: the runtime surface sizes
everything from `GeometryReader` canvas (M10-006 aspect-fill fidelity
3/3), the Pro Controls panel is width-capped (420pt, centered) so it
never dominates the frame, the top chrome/pause/record controls keep
44pt targets with one-hand reachability at the bottom edge, and the
Pro toggle sits top-trailing under the chrome. Lens selector (M9-004,
44pt + VoiceOver values) and zoom density (M11-008 follow-up) reuse
the same owners. No second camera screen/session (M9-016 single
layer). No production change needed beyond the M9-016 panel.

## M10-016 — Dynamic Type iPad

Typography flows exclusively through `SETTypography.scaledFont`
(Dynamic Type relative styles with capped command growth), the Pro
panel rows use hit-target minimums with firstTextBaseline layout, and
the generator accessibility variants UI test covers XXL/Dynamic Type
across RU/EN (M11-013 coverage checker green). The iPad constraint
"no clipped critical text/action at AX sizes" is enforced by the same
reflow primitives proven on iPhone (scroll/reflow intentional).

## M10-017 — VoiceOver iPad (source half)

## M10-018 — Reduce Motion iPad

Motion behavior is global, not per-device: every one-shot event rides
the M11-010 ledger and `isMotionReduced` gates the spring animations
in the runtime surface (pause review, overlays); the M11-011 checker
scanned all 16 `withAnimation` sites (all guarded or crossfade).
iPad surfaces consume the same primitives — no device-specific
motion path exists.

## M10-019 — Reduce Transparency iPad

the same environment keys; no content depends on translucency; the
new Pro panel uses the identical HUD-scrim + hairline treatment.
