# Анализ качества датасета Camera Coach — v1 (только анализ, без изменений)

Дата: 2026-09-23. Основание: прямая просьба владельца («подумай хорошо и максимально внимательно, в чем проблемы датасета? как его улучшить? — пока только подумай, не переделывай»). Датасет НЕ менялся; все факты — свежие замеры по текущему дереву `local-data/SETOS` (после вчерашнего удаления дубликатов) и существующие ресипты.

## 1. Метод

Разрешения: случайная выборка 40 файлов на семью (seed 7), `PIL.Image.size`, долгая сторона. Counts — DATA-003/GOV-007 ресипты. Правовые статусы — DATA-003 (rights tiers) и политика AVA (`17-ava-usage-policy…`). Доменная оценка — по происхождению семей.

Итого: **~14 500 файлов (aadb+eva+мелкая часть temporal) — ниже 700px** — это и есть «пиксельные фотографии», которые непонятно как размечать. Ещё ~9 000 (cinematic+ava) — чужой домен (CG/кино). Реально полезное ядро ≈ 14k файлов webresearch+photography, из них без курируемой связи с дефектами — большая часть.

## 3. Корневые проблемы (в порядке вреда)

1. **Несоответствие продукту.** Продукт коучит живую iPhone-съёмку (портрет/объект/комната, ошибки фокуса/света/кадра). В датасете почти нет кадров, снятых телефоном с типичными любительскими ошибками. Модель, обученная на веб-эстетике и CG, будет решать чужую задачу.
2. **Разрешение/сжатие.** Медианы 256–640px у трети пула: модель учится детектировать JPEG-артефакты вместо съёмочных дефектов; разметчик не может оценить фокус/шум на миниатюре (твоё «непонятно как размечать»).
3. **Отсутствие меток у «полезного» ядра.** webresearch/photography не размечены и не стратифицированы по 10 группам §4 — ценность не извлечена, размечать наугад 12k кадров — потеря твоего времени.
4. **Целевая переменная не та в aesthetic-MOS семьях.** AVA/AADB/EVA измеряют «нравится/не нравится», а нам нужен «вердикт + одна выполнимая правка + уверен/не уверен». MOS-корпуса в лоб дают нерелевантный supervision.
5. **Нет интентов.** Невозможно отличить намеренный low-key/silhouette от недосвета → отравление good-frame head (ложные «исправь» на стильных кадрах). В пилоте это выльется в «не понимаю замысел» — этот сигнал надо собирать и возвращать в датасет тегами.
6. **Перекос и протечка.** lasiesta+scenetrans доминируют; CG и фото смешаны в одном пуле; сплиты по семьям есть, но доменного флага (cg/photo) нет — валидация может мерить CG, а продукт — фото.
7. **Дефекты ненастоящие.** Синтетические порчи — геометрия (crop/rotate/zoom); реальные ошибки (смещённый фокус на лице, тряпка, грязная линза, жёсткая тень) отсутствуют; порчи применялись к уже-сжатым базам.

## 4. Что можно автоматизировать (план, НЕ исполнялся)

1. **Скорборд-фильтр** (скрипт, только помечает, ничего не удаляет): разрешение ≥1000px; оценка JPEG-качества (кван-таблицы); резкость (дисперсия Лапласиана); near-dup; детект текстовых кадров (титры) для cinematic; доменный флаг `cg` для рендеров. Выход: `keep / review / out` + причина на файл + сводка. Убирает п.2 автоматически.
2. **Пересборка тренировочного пула** под квоты §4 из отфильтрованного ядра: cap по семьям, стратификация по предсказанному matrix_class (Apple Vision на хосте уже делали в silver-fit) — чтобы разметчик получал только кадры, достойные разметки.
3. **MOS-семьи → отдельный pretraining-лейн** (ava/aadb/eva никогда не попадают в release-пул; закрепить в манифест-билдере кодом, не прозой).
4. **Порчи только на хороших базах**: геометрия уже есть; добавить exposure/WB/шум/мыло на отфильтрованные ≥1280px базы; каждая порча = аналитическая метка (готовый генератор `generate_camera_corruptions.py` расширить). Плюс **hard negatives**: незаметные трансформации хороших кадров с меткой «good» — лечит ложные срабатывания.
5. **Доменные флаги + сплиты**: `domain: photo|cg|scan` в манифесте; сплиты по family×author×near-dup×domain — валидация мерит фото-домен.
6. **Сигнал «не понимаю замысел» → датасет**: из нового fast-tool такие кадры автоматически получают `intent_ambiguous` и либо выводятся из пула, либо получают интент-тег после уточнения; аналогично время на кадр <порога → очередь переразметки.
7. **QC-сиды из аналитических пар** (уже строится в fast-tool): согласие аннотатора с известным ответом — метрика качества разметки, а не только модели.

## 5. Что требует владельца (не автоматизируется честно)

- **iPhone-нативная съёмка** по shot-list SL-01…10 (10 сценариев): это единственный источник кадров, действительно похожих на пользовательские; автоматизирую приёмку (EXIF/линза/хеш/манифест), съёмка — твоя.
- Решения по правам на добор (DATA-015 манифесты готовы).
- Съёмка before/after эпизодов (DATA-013) — 5–10 минут на серию, критично для верификации «исполнено/нет».

## 6. Порядок применения (когда скажешь)

Этап 1 (полностью авто): скорборд-фильтр + пересборка пула под квоты + доменные флаги — pilots-очередь 100 кадров заменяется на «достойные разметки» кадры. Этап 2 (авто после пилота): расширение порч + hard negatives. Этап 3 (владелец): iPhone-съёмка и эпизоды. Никаких удалений: всё «out»-помеченное остаётся на диске с флагом.

## 7. Чего сознательно НЕ делаем

Не удаляем MOS/CG семьи (pretraining-ценность и история); не смягчаем права; не подгоняем квоты ради цифр; не запускаем тяжёлую обработку без команды (диск/энергия).
