Контекст: владелец (единственный аннотатор) отказался от `annotate_gui.py` («перегруженный,

## Что создано (только новые файлы)

- `tools/camera_annotation/annotate_fast.py` — визард + чистая логика + CLI:
  - FSM `FrameFlow` (чистый, без tkinter) — вся логика потока отдельными тестируемыми
    функциями/классами; tkinter-слой `_FastApp` тонкий (картинка, вопрос, статуса).
  - Машинные бакеты: severity 1/2/3 → 0.3/0.6/0.85; confidence 1/2 → 0.9/0.6;
    «не могу указать» ([X]) снижает уверенность на шаг → 0.6/0.45. Никаких слайдеров.
  - issues: 15 heads контракта в 3 группах с буквами (легенда на экране, выбранное
    подсвечено); рамка мышью для последней выбранной issue; [R] «весь кадр»,
    [X] «не могу указать».
  - action: шорт-лист только релевантных действий — фильтрация выбранных issues через
    DATA-002 (`camera_release_capability_mapping_v1.json`, ровно `disposition=mapped`;
    проверяется тестом против реального файла). Нет релевантных → [N] «нет подходящего
    действия» → честное воздержание (abstain `unsupported_case`), выбранные проблемы
    сохраняются в regions/detail/заметке.
  - «НЕ ПОНИМАЮ ЗАМЫСЕЛ» [U] — первоклассный путь: 4 подсказки причины
    (unsupported_case / ambiguous_subject / unqualified / missing_evidence) + одна
    необязательная строка «что смущает?»; экспорт — abstain с явной причиной.
  - Защиты: dwell-time (<1.5 сек на needs_fix кадре — мягкое предупреждение, не блок);
    блок «issues + good» (выбор issue из confirm-keep переспрашивает вердикт 2/3/U);
    санити issue↔action перед сохранением (пример спецификации underexposure+level_horizon
    ловится механизмом покрытия); [3] «плохой» → обязательный вопрос о намеренном стиле,
    Y → keep с обязательной заметкой (контракт ugly+keep требует note).
  - Скрытые QC-сиды: детерминированное подмешивание 5–7% очереди (для 100 кадров — 6,
    позиции равномерные), результат сидов пишется в отдельный `qc.jsonl`, в UI сиды
    неотличимы от кадров очереди; `--report-qc` печатает agreement (verdict/issue/action).
  - Автозаполнение: record_id, все ID, хеши, evidence_refs («{record}.r{i}» с рамкой,
    «{record}.frame» без), entity_ref «subject-1»; captured_at НЕ выдумывается.
  - Всё append-only, ничего не пишется до Enter; `session.json` в каталоге очереди —
    закрыл и продолжил; B — предыдущий кадр (правки = новая запись, старая не
    переписывается); Esc — шаг назад.
  - Буквенные горячие клавиши работают и в русской раскладке (keysym переводится
    по физическим позициям ЙЦУКЕН); печать заметки не перехватывается визардом
    (буквы уходят в поле ввода, Return/Escape управляют потоком).

## Отклонения от спеки (технически неизбежные, с причинами)

1. **Добавлен шаг «рамка главного объекта» (6a)** для 27 действий, где контракт релиза
   (`camera_release_label_v1.schema.json`, allOf[6]) требует `identity_status=resolved` +
   непустой регион таргета. Спека говорила «target=primary subject (auto)» — авто-таргет
   без человеческой рамки не проходит валидатор DATA-001, а выдумывать регион машина
   отказывается. Рамка берётся мышью; [R] «весь кадр» ([0,0,1,1]) допустим для не-перемещающих
   действий; для перемещающих — обязательна (трекер §4: конкретная команда без
   подтверждённого региона запрещена). Для stabilize/reduce/increase_exposure шага нет.
2. **Вопрос movability расширен** против списка «move_object*/move_subject*/rotate_subject*»:
   schema allOf[7] требует `movability=movable/allowed` также для `remove_distracting_object`,
   `reposition_prop_for_balance`, `move_subject_away_from_background` — вопрос задаётся для
   всех действий этого условия. Ответ [N]/[?] с перемещающим действием даёт предупреждение
   (экспорт отклонит схема `allowedMovability`): Esc назад к выбору действия или продолжить.
3. **15 heads vs v1-словарь (главное ограничение)**: спека требует 15 heads в визарде И
   v1-совместимые записи через `build_label`. Но v1-хранилище (`annotation_labels.py`,
   менять запрещено) знает только 8 issues и 26 действий; 7 технических heads
   (motion_blur, defocus, overexposure, underexposure, noise, occlusion, lens_smudge) и
   технические действия (stabilize_camera, refocus_subject, reduce/increase_exposure,
   avoid_occlusion, …) существуют только в release-контракте, и цепочка
   v1→release (адаптер) их отвергает. Решение: визард предлагает все 15 (как в спеке);
   v1-запись пишется только когда v1 может её закодировать — issues пересечением со
   словарём v1; если выбор чисто технический — v1-записи нет вообще (честное отсутствие
   вместо выдуманной совместимости); полная 15-head правда всегда в `fast_details.jsonl`;
   экспорт записей, выходящих за v1-словарь (в т.ч. mixed), честно REJECTED с явной
   причиной, ничего не записывается. Предупреждение видно аннотатору до сохранения.
   Расширение v1-словаря — отдельное решение владельца (DATA-009 может его поднять).
4. **kind таргета** для авто-таргета = generic `object` (у схемы нет kind=unknown);
   `person` выводится детерминированно для move_subject*/rotate_subject*. entity_ref
   всегда «subject-1»: вывод entity из рамок проблем выдумывал бы identity.
5. **captured_at**: очередь пилота и v2-манифест не несут wall-clock времени съёмки
   (только nominal ffmpeg timeline). По правилу «не выдумывать» экспорт всех пилотных
   записей будет честно REJECTED по captured_at, пока не появится provenance-источник.
   Happy-path экспорта доказан юнит-тестом на записи с настоящим captured_at
   (adapter EXPORTED + `RELEASE LABEL VALID`).
6. **Keep без заметки** (2-нажатный путь) допустим на сохранении (v1 разрешает), но
   экспорт отклонит её (конверт требует raw opinion) — подсказка на экране; [W] добавляет
   заметку перед сохранением.
7. **Сиды все composition-группы**: все три белых рецепта дают issues horizon/edge —
   strata_group сидов честно «composition». Замечено при сверке: crop_zoom_in в парах
   несёт `subject_too_close_to_edge` (не prominence) — ожидания строителя сверяются с
   positives каждой пары, не с предположениями.

## Как пользоваться (шпаргалка владельца)

Запуск (файлы появятся в каталоге очереди):

```bash
cd /Users/unterlantas/Documents/XCode/shafinMultitool
python3 tools/camera_annotation/annotate_fast.py \
  --queue /Users/unterlantas/Documents/XCode/setos-backend/local-data/SETOS/annotation/pilot-20260923-strata-v1/queue.jsonl \
  --annotator-id "rustem"
```

Клавиши:

- `1` хороший · `2` норм, но улучшить · `3` плохой · `U` НЕ ПОНИМАЮ ЗАМЫСЕЛ · `S` пропуск
- хороший → `Enter` = сохранить (2 нажатия на кадр); `W` = заметка; любая буква проблемы = передумал
- `3` → `Y/N` «намеренный стиль?»; `Y` → обязательная заметка
- `U` → причина `1..4` → строка «что смущает?» (можно пусто, `Enter`)
- проблемы: буквы из трёх групп на экране (несколько); рамка мышью — к последней выбранной;
  `R` весь кадр · `X` не могу указать (−уверенность); `Enter/пробел` — далее
- действие: буква из короткого списка · `N` нет подходящего действия
- `1/2/3` насколько плохо · `1/2` насколько уверен
- «объект можно передвинуть?» (для действий с объектом): `Y` можно · `N` нельзя · `?` не знаю
- рамка объекта (когда попросит): мышью + `Enter`, `R` весь кадр (если допустим)
- заметка: текст + `Enter` (необязательна, но экспорт требует непустую)
- `Esc` — шаг назад · `B` — предыдущий кадр (правка = новая запись) · `→` — вперёд
- закрыть можно в любой момент: `session.json` сохраняет прогресс

Отчёт по скрытым сидам (после разметки):

```bash
python3 tools/camera_annotation/annotate_fast.py --report-qc \
  --queue …/pilot-20260923-strata-v1/queue.jsonl
```

Экспорт release-label (fail-closed; сейчас пилотные записи будут отклонены по
captured_at/v1-словарю — это честно, см. отклонения 3 и 5):

```bash
python3 tools/camera_annotation/annotate_fast.py --export-out DIR --queue …/queue.jsonl
```

## ДОПОЛНЕНИЕ 2026-09-24: кнопка [A] «контрактом не выразить»

Реализация (tools/camera_annotation/annotate_fast.py):
- Экран «Что не так?»: клавиша **[A]** (G занята «пересветом») → флаг contract_gap + шаг
  gap-заметки (одной строкой, можно пусто; Esc снимает флаг и возвращает к проблемам).
- Если проблемы уже выбраны — флаг едет вместе с обычным потоком (действие →severity→…).
- Если проблем нет — `_finish_gap`: честное воздержание, v1-запись unsure
  (причина unsupported_case, notes = текст владельца), detail.verdict=«contract_gap»,
  nominal_verdict сохраняет исходную оценку 1/2/3.
- Экспорт: такие записи проходят контракт как abstain (unsupported_case) — текст остаётся
  raw opinion рядом; v1_incomplete-логика не затронута.
- Новый отчёт `--report-gaps`: список всех contract_gap записей (id, вердикт, текст,
  выбранные issues) — вход на доработку контракта v2.
- back() чистит флаг при уходе с gap-шага; _apply_restore восстанавливает флаг/заметку.

Тесты: +4 (40 total; смежные сьюты 83 passed): флаг с выбранными проблемами едет в действие;
[А]-без-проблем → валидный v1 unsure + unsupported_case + текст в notes; Esc снимает флаг;

Границы: текст gap-заметки никогда не становится меткой; изменение 15-head словаря
