## What was fixed

1. `SETMetrics.swift` — `SETCameraCoachRailContent` gained optional `supportingObservation` and `stackedActionLabel` (backward-compatible init defaults). `liveRailHeight` gained `contentSizeCategory: UIContentSizeCategory? = nil` (nil = the process' current category, i.e. exactly what the render sees). `measuredLiveRailHeight` now measures with `UIFontMetrics`-scaled fonts mirroring the render contract: observation `hudMono/body` relative to `.body`; action `display/command` relative to `.headline` clamped to `[command, commandMaximum]` (22…34) bold — the same clamp as `SETCommandLabel`; supporting/label relative to `.caption2`; the stacked action keeps at least the 44 pt hit target; controls height accounts for scaled label line height. New typed helpers `scaledUIFont(role:size:relativeTo:compatibleWith:)` and `clampedScaledCommandUIFont(compatibleWith:)`.
2. `SETCameraCoachProductionView.swift` — command band observation and status-overlay observation now use `SETTypography.scaledFont(.hudMono, size: .body, relativeTo: .body)` and keep `.fixedSize(horizontal: false, vertical: true)` (multiline, never truncated); supporting observation uses scaled `.caption2` with `lineLimit(1)` removed; status-overlay action uses `@ScaledMetric(relativeTo: .headline)` clamped to `[title, commandMaximum]`; the status rail height is now measured from `statusRailContent` (observation + supporting + stacked action) instead of the static profile.
3. `SETComponents.swift` — `SETPauseReviewBand` title scales relative to `.body` and wraps without `lineLimit(2)`/`minimumScaleFactor(0.82)`; the band lives inside the review `ScrollView`, so growth is absorbed by reachable scroll and the primary action (`SETPauseReviewBand` is its first child; `SETPauseReviewBand` is used by the camera surface only, `:2529`) stays reachable.
