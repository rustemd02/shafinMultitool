## 1. Проверенный факт (root cause — кодом, не догадкой)

`queue-v2-diverse.jsonl` (sha `3519f675e913…`) содержал record_id `pilot23-composition-07`
**дважды, на разных кадрах**:

| Строка | package_record_id | image_sha256 |
|---|---|---|
| 2 | `photo__scenetrans_bedroom_shelf_pairs_20260914__2_items__pair_0186__B` | `02903aa6…` |
| 7 | `photo__commons_scenario_photo_candidates_20260914__101220534` | `c9b2b39a…` |

`annotate_fast.py` строит `items_by_id = {r["record_id"]: r for r in queue}` (dict; последнее
вхождение побеждает) и показывает/пишет кадр через `record_for(rid)` → `items_by_id.get(rid)`.
Следствие: **обе позиции обхода показывали commons-кадр** (строку 7); scenetrans-кадр
не показывался никогда. Сессионный обход (`session.json.record_ids`) содержал ID на позициях 2 и 7.

Следы в сохранённых записях подтверждают вывод (независимо от кода): обе пары записей
`pilot23-composition-07` (`fast_labels.jsonl` строки 3/8, `fast_details.jsonl` строки 3/8)
несут `image_sha256 = c9b2b39a…` (commons) с разным dwell (13.7 c / 38.9 c) — это два прохода
по одному изображению; времена сохранений идут ровно по позициям обхода 1…8.

## 3. Ремонт (человеческие записи не тронуты)

Принцип: human-записи священны; record_id — alias, контент-идентичность = `image_sha256` +
`package_record_id` (DATA-007). Поэтому ID `pilot23-composition-07` остаётся за тем кадром, к
которому привязаны human-записи (commons `…101220534`), а неразмеченная строка получает свежий ID.

1. Строка 2 очереди: `pilot23-composition-07` → **`pilot23-composition-11`** + поле
   `record_id_history: ["pilot23-composition-07"]`. Все остальные 99 строк — байт-идентичны
   (проверено сравнением строк; изменена ровно строка 2).
   Правило выбора ID: первый `pilot23-composition-NN`, не занятый ни одним кадром во всём
   пространстве имён `pilot23-*` (01–10 заняты v1-очередью; `02` в v1 = другой кадр).
2. `session.json`: позиция обхода «pilot23-composition-07» → `pilot23-composition-11` перенесена
   в **конец обхода** (неразмеченный кадр будет показан последним, уже размеченные не
   переспрашиваются); `index` = первый неразмеченный (`pilot23-composition-09` — ровно то место,
   где владелец остановился); `queue_sha256` обновлён на sha repaired-очереди (иначе инструмент
   честно сбросил бы прогресс при следующем запуске); `done` не менялся —
   `pilot23-composition-07` = commons-кадр, он размечен (2 прохода).
3. Исходные байты: `identity-repair-20260927/queue-v2-diverse.jsonl.orig`,
   `identity-repair-20260927/session.json.orig`; карта old→new — `migration-manifest.json`.
   Исторические ресипты (2026-09-23/24, sha `3519f675…`) **не переписаны** — правило §0.

Хеши: очередь `3519f675e913…` → `dd47f199ba40…`; сессия `ab96a995e6f0…` → `031188d6eef5…`
(обе копии `.orig` сохранены рядом); `fast_labels.jsonl` `f189169c8e67…` и
`fast_details.jsonl` `25e3b0597072…` — **не изменялись**.
