# Предложение: источник признака намеренности для вердикт-деривации критика

Статус: 2026-09-12, проект для согласования с владельцем (D1/D4/D6-область). Автор — ИИ-исполнитель; решение не принято.

## 1. Проблема (сvidence)

Детерминированный критик (`FrameCritiqueEngine`) не имеет признака намеренности сцены. На контрольном наборе `camera_device_benchmark_pack_v1` (174 записи с курируемыми лейблами):

- **128/174 (74%) записей** расходятся с лейблами по семантическим действиям; **26** попадают в forbidden-действия (`evidence-m2/still-replay-label-drift-dump-20260912.txt`);
- 38 кадров с лейблом `good` (нулевые курируемые problems) получают вердикт `mixed` (11) или `needs_fix` (27) с корректирующими советами;
- **визуальная верификация** трёх ключевых кадров подтверждает правоту лейблов: ca_img_009 — намеренный тайт-кроп портрета (runtime советует «move_object_right»), ca_img_017 — рабочее интервью (runtime советует «simplify_background, move_object_back»), ca_img_036 — художественный лоу-кей (runtime советует «increase_exposure, reduce_iso_noise» — лечит стиль как дефект).

Два пороговых эксперимента калибровки **без intent-признака** дали net-отрицательный результат и были откачены: снятие `edgePressureScore ≤ 0.80` из `subjectReadable` улучшило still-replay (−3), но сломало live-цепочку (+10); деградация edge-pressure ×0.50 в pause ухудшила suite (37→39). Причина: отличить «намеренный кроп/темнота» от «дефекта» по текущим feature-признакам невозможно — нужен независимый сигнал намерения.

## 2. Варианты источника намеренности

### Вариант A — aesthetic/intent-модель (M-lane, рекомендован в фоновой работе)

Лёгкая модель (он-девайс, Core ML), обученная на кураторских лейблах этого же пака (174 записи — готовое ядро) + существующем research-корпусе (15 301 изображение), предсказывает класс намерения/качества кадра. Её выход включается как evidence-вход критика: существующие подавители (`hasAestheticIntentionalEdgeComposition`, `shouldPreserveLowKeyMoodKeepCurrentSetup` и др.) уже ждут этот сигнал и оживают автоматически.

- Плюсы: он-девайс, приватность, детерминизм, подавители уже написаны под этот контракт.
- Минусы: нужен compute-бюджет на обучение (Colab), валидация на независимой выборке (master §9.6), research-lineage нельзя автоматически сделать коммерческим.
- Срок: дни на пилот, недели на qualified-модель.

### Вариант B — VLM intent-слой (D1-gated)

Облачный VLM по явному согласию пользователя классифицирует намерение кадра (low-key/документальный/предметный/силуэт) как evidence для подробного (pause) разбора.

- Плюсы: широкое семантическое понимание без обучения.
- Минусы: egress-consent (D1), стоимость/лимиты, latency, недетерминированность — непригодно для live-конвейера; только pause/разбор.
- Зависимости: D1 (egress scope), провайдер и бюджет (D3).

### Вариант C — интерактивное уточнение намерения (CC-I05, уже в требованиях)

Live-UX: при спорном стиле/композиции система спрашивает «это намеренно?» и запоминает suppression в рамках эпизода/сеанса.

- Плюсы: нулевая инфраструктура, честный отказ вместо уверенной ошибки, уже предусмотрено requirements (CC-I05) и доменным контрактом.
- Минусы: не закрывает replay-калибровку и pause-разбор без пользователя.

### Вариант D — статус-кво (документированный drift)

Deterministic critic уверенно ошибается на 38 good-кадрах (худший вариант: уверенная ошибка вместо воздержания), 41 тест остаётся красным. Не рекомендуется.

## 3. Рекомендация

Комбинация **C + A**: немедленно — интерактивное уточнение (C) в live/pause UX как честный механизм; параллельно — обучение intent/aesthetic-модели (A) на кураторском ядре для автоматического подавления в replay и pause. Вариант B — опционально позже, при согласованном D1-egress для подробного разбора.

## 5. Feasibility-исследование (2026-09-12, выполнено)

**Пилот вариант A исполнен**: `ml/camera_coach/intent_pilot/` — детерминированный датасет-билдер (стратифицированный сплит 122/52, seed 20260912) + softmax-LR пилот (numpy, гиперпараметры по validation). Результат: 3-class test accuracy **0.673** (baseline 0.466); good F1 0.702, bad F1 0.698, mixed F1 0.0 (support 4). Подтверждает выводы ниже: текущие признаки дают сигнал, но недостаточны для master-гейтов — вариант A требует qualified модели на расширенном intent-корпусе. Пайплайн воспроизводим и переиспользуем для будущих признаков.



Полный дамп 174 записей с полными feature-профилями (`evidence-m2/intent-features-full-dump-20260912.txt`), softmax-LR leave-one-out:

- 3-class (good/mixed/bad): LOO accuracy **0.638** при majority-baseline 0.466 — сигнал есть, но недостаточен для master-гейтов.
- Binary good-vs-rest: **0.713** (baseline 0.534).
- Единственный сильный признак: `aesthetic_score`, AUC **0.836** (good-кадры имеют более высокий score: 0.449 vs 0.397).
- Лучший однопороговый гейт T=0.42 (совпадает с существующим подавителем): точность 0.793, но **18 label-bad/mixed кадров ошибочно получают keep** — лёгкий эстиматор систематически занижает лоу-кей/художественные кадры.

**Вывод**: детерминированный гейт на текущем score исключается (вариант A-lite); вариант A (qualified модель) подтверждён данными — текущий score не пригоден как intent-признак без переобучения на intent-задачу.
